# E1 Flight Agent 机内安全门协议

本协议建立 Agent 入口、解锁安全检查、停止能力和受保护的高层技能入口。它不允许 Agent 直接写电机、姿态目标、参数或控制台命令。

## 固定 MAVLink 边界

- 消息：`COMMAND_LONG`（消息号 76）
- 项目私有命令：31010（MAVLink 用户自定义命令区）
- 飞控目标：系统号 1、组件号 1（`MAV_COMP_ID_AUTOPILOT1`）
- Agent 来源：系统号 42、组件号 191（`MAV_COMP_ID_ONBOARD_COMPUTER`）
- Agent 心跳发送间隔：不超过 250 ms
- Agent 心跳超时：1000 ms

固定来源号只能防止误接线和限制模型进入旧的直控入口，不是密码学身份认证。知道这些编号的其他发送方可以仿冒 Agent。

`COMMAND_LONG` 参数固定如下：

| 字段 | 含义 | 允许范围 |
|---|---|---|
| `param1` | 技能编号 | 下表中的整数 |
| `param2` | 请求编号，用于防止重复执行 | 1 到 16777215 的整数 |
| `param3` | 安全确认码 | 固定为 7319 |
| `param4` 到 `param7` | 高层技能参数 | 按对应技能的固定范围 |
| `confirmation` | MAVLink 重传计数 | 0 到 255；不代替 `param2` |

## 技能白名单

| 技能编号 | 名称 | E3T1 行为 |
|---:|---|---|
| 1 | Agent 心跳 | 建立或刷新会话 |
| 2 | 解锁 | 全部安全条件通过后才解锁 |
| 3 | 上锁 | 立即上锁并清零推力目标 |
| 4 | 急停 | 无条件上锁、清零推力目标并锁存故障 |
| 100 | 起飞 | 安全门和状态机均接受后才启动 |
| 101 | 降落 | 安全门和状态机均接受后才启动 |
| 102 | 悬停 | 安全门和状态机均接受后才启动 |
| 103 | 机体系移动 | 安全门和状态机均接受后才启动 |
| 104 | 偏航 | 安全门和状态机均接受后才启动 |
| 105 | 返回局部原点 | 只返回本地原点；不是 GPS 返航 |

重复的已执行请求返回成功但不会再次执行。未知技能、错误确认码、错误参数、错误目标或其他 Agent 消息会锁存故障。锁存后 Agent 不能再次解锁；E3T1 不提供 Agent 自行清除故障的命令，需要人工检查后重启飞控。

高层技能先经过安全门，再进入电脑端可验证的飞行技能状态机；只有两层都接受，`COMMAND_ACK` 才返回成功。安全门会在非法参数、未由 Agent 解锁、心跳过期、人工接管、低电、倒置或姿态无效时拒绝，状态机也会拒绝不健康的传感器。重复的已成功技能不会再次启动。状态机的拒绝会作为结果 34 返回，并可从状态机故障状态观察原因。

当前生产固件没有接入真实传感器驱动或状态估计，因此不会提交任何健康传感器数据，也不会伪造可用飞行状态；所有高层技能都将失败关闭。状态机只生成受限软件目标，尚未接入 PID、姿态目标、电机混控或电机，也没有接入实时大模型控制环。

## 解锁和运行时检查

解锁前必须同时满足：

- 飞控当前未解锁；
- 油门不高于 5%；
- 姿态有效且四元数长度在 0.9 到 1.1 之间；
- 机体未倒置；
- IMU 初始化成功；
- 单节电池电压在 3.5 V 到 4.4 V 之间；
- 飞控判断机体已经落地且静止；
- Agent 心跳未超过 1000 ms；
- 没有人工遥控输入；
- 没有已锁存故障。

Agent 会话中发生心跳超时、人工遥控介入、低电、倒置、姿态失效、未知技能或非法消息时，安全门进入锁存故障状态。若当前解锁由 Agent 发起，则立即上锁并清零推力目标。人工遥控和急停优先于 Agent；Agent 未取得解锁权时，安全门不会改写非 Agent 的既有人工遥控行为。

## 必须拒绝的 Agent 消息

来自固定 Agent 来源的 `MANUAL_CONTROL`、`PARAM_SET`、`SERIAL_CONTROL`、`SET_ATTITUDE_TARGET`、`SET_ACTUATOR_CONTROL_TARGET`，以及通用解锁、改模式命令，全部在旧处理分支之前拒绝。来自其他来源的原有人工遥控处理保持不变。

飞控使用 `COMMAND_ACK.result` 返回 MAVLink 标准结果，`progress` 固定为 `UINT8_MAX`。`COMMAND_ACK.result_param2` 是固定的非负 v1 元数据：低 24 位为原始请求编号（0 到 16777215），第 24 到 30 位为安全门结果编号，最高位始终为 0。结果编号中，0 表示接受，1 表示重复请求，20 到 28 表示当前安全条件不满足，30 到 33 表示已锁存或协议违法，34 表示状态机未接受该技能。只要请求编号本身能精确解析，即使目标、技能、确认码或其他参数无效，ACK 也会原样回传它；只有请求编号无法精确解析时才回传 0。Mac 必须同时匹配命令和这个请求编号，不能把延迟或重复的旧 ACK 当作下一条请求的结果。

## 动作状态回传（AGT_STAT v1）

`COMMAND_ACK` 只表示请求已经被安全门和状态机接受，**不表示动作已经完成**。在
`WIFI_ENABLED` 的 MAVLink 发送入口中，飞控额外使用 MAVLink common 的
`NAMED_VALUE_INT` 回传当前状态；它只读取已有状态，不写电机、PID、姿态或控制目标。

- `name` 固定为 `AGT_STAT`。
- `time_boot_ms` 固定为发送当刻的 `millis()`。
- 最大发送频率为 10 Hz；不发送电机、PID、姿态或目标值。
- `value` 是一个非负的 32 位整数。Mac 必须按下表解码，不能把保留位或未知版本当作有效状态。

| 位 | 宽度 | 字段 | v1 允许值 |
|---|---:|---|---|
| 0–2 | 3 | 协议版本 | 固定为 1；其他值拒绝解析 |
| 3–5 | 3 | 任务状态 `MissionState` | 0 空闲、1 运行中、2 失效降落、3 完成、4 失败 |
| 6–8 | 3 | 当前执行技能 `active Skill` | 0 无、1 起飞、2 悬停、3 机体系移动、4 偏航、5 返回局部原点、6 降落 |
| 9–11 | 3 | 最近完成技能 `completed Skill` | 沿用当前执行技能的编号表；0 表示本任务尚无已完成技能 |
| 12–16 | 5 | 飞行状态机故障 `Flight Fault` | `flight_skills::Fault` 的 0–18；0 无故障 |
| 17–19 | 3 | 最近目标动作 `last Target Action` | 0 无、1 跟踪、2 降落、3 冗余降落、4 紧急下降、5 请求上锁、6 中止 |
| 20–22 | 3 | Agent 安全门故障 `Agent Fault` | 0 无、1 心跳超时、2 人工接管、3 低电、4 倒置、5 姿态无效、6 非法消息、7 急停 |
| 23 | 1 | `agentOwnsArm` | 1 表示当前解锁权属于 Agent |
| 24 | 1 | `armed` | 1 表示飞控当前已解锁 |
| 25 | 1 | `manualControlActive` | 1 表示当前有人为遥控输入 |
| 26 | 1 | `heartbeatFresh` | 1 表示 Agent 心跳仍在 1000 ms 有效期内 |
| 27–28 | 2 | 安全门状态 | 0 空闲、1 就绪、2 Agent 已解锁、3 故障已锁存 |
| 29 | 1 | `landed` | 1 表示飞控当前判定已落地且静止 |
| 30–31 | 2 | 保留 | v1 必须为 0；非零拒绝解析 |

Mac 的判读顺序必须是：先以 `COMMAND_ACK` 判断请求是否被接受；随后看到“任务运行中且当前执行技能非零”才表示正在执行；“任务运行中、当前执行技能为零、最近完成技能非零”表示该技能已经完成；任务状态为“完成”才表示整个任务成功结束。任一故障字段非零、任务处于失效降落或失败，都不能当作完成。人工接管通过 `manualControlActive` 和 Agent 安全门故障值 2 可直接观察。

主机可运行下面的检查来固定这些位域、拒绝路径、MAVLink common 消息名称和 10 Hz 上限：

```bash
./scripts/check_firmware.sh status
```

本改动沿用上游 `songge8/CF-Drone` 的飞控实现和仓库 `LICENSE`，保留琛光品牌及原启动文字。
